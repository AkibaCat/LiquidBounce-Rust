# AutoQueue source port

Source: LiquidBounce ae0eb396 `ModuleAutoQueue` and all preset, trigger,
item-selection and action files under `modules/player/autoqueue`, together
with `CoroutineTicker`, accepted `ChatReceiveEvent` and the native
`MultiPlayerGameMode.useItem` call boundary. Category Player; alias AutoPlay.
The module defaults to HypixelSW and keeps all four source pause conditions.

HypixelSW watches the actual hotbar for paper, sends the selected Normal or
Insane solo command, then waits twenty ticks. GommeDuels reads the actual tab
header and searches armor stands by their team-formatted display name and
eye-to-box distance, then world players by position and distance. The lobby
interaction sends the ordinary entity interaction without an extra reach or
rotation requirement. Its five-second lobby and two-second victory/defeat
waits use real elapsed time, resumed by the shared FIFO ticker. The head-item
path uses its own silent-slot requester, five ticks before the explicit
predictive UseItem packet and twenty ticks after it.

Custom retains all source triggers and settings. Message triggers distinguish
accepted signed player chat, accepted disguised chat and game/system messages;
title and subtitle use their actual receive callbacks. Item selection checks
the offhand before hotbar slots and supports all eight source name matching
modes and registry items, including explicitly selected empty air stacks.
The native hover-name helper retains potion, book and component names.

Custom Chat captures the original message list but reads each subsequent delay
at its source point. Its kotlinx `delay` equivalent uses a native Main event
loop wake between ticks; it is separate from Gomme's tick-polled real-time
waits. Custom UseItem selects the captured matching slot with a separate
twenty-tick requester, checks the current action pick against that slot while
suspended, waits one tick and calls the genuine native useItem path. This
direct caller ignores the result and does not add Minecraft.startUseItem's
equip-height reset or swing. The guard remains active across a world-change
wait and the final twenty-tick cooldown. Pause conditions prevent new runs
without cancelling an already suspended source sequence.

The source subtitle trigger is deliberately also named `Title`. JSON object
serialization therefore retains the later subtitle settings under the same
key, mode selection chooses the first Title mode, and imported Title keywords
update both modes. This pinned upstream collision is preserved rather than
renamed. The internal subtitle branch remains implemented.

KillAura and Speed control resolves real registered modules dynamically.
Neither dependency is currently implemented/registered in the host; missing
modules are skipped. Those controls become active when their genuine module
implementations are integrated. Module disable resets the Gomme requester
only; the Custom requester expires naturally, as in the source. Source module
control does not restore prior enabled states on disable.
