# Shared Clicker dependency

Owned `liquidbounce-behaviors/src/clicking.rs` ports LiquidBounce ae0eb396 `utils/clicking/{ClickPlan,Clicker,HumanClickTiming,ConstantClickTiming,ItemCooldown}.kt`. It is a dependency for upcoming TriggerBot/AutoClicker, with no module registration or native hooks in this delivery. The integration owner applies `integrate-clicking.py --apply`; default/`--check` is memory-only.

Planning keeps the source's monotonic 50ms grid, 1000ms horizon, strict >250ms idle reset, 32-entry history, inclusive end/exclusive start buckets, MaxPerTick spacing, dynamic CPS and cap replanning, and technique changes that keep the preplanned horizon. Real player presses replace the next plan entry. Another same-mapping click consumes the follower's current budget then adopts the leader's future timestamps.

The scheduler retains nullable clickAmount, cumulative calls in a tick, wrapping source Int counters, dropped failed attempts, live cooldown and missTime gate reads on every attempt, successful-click callback before the next attempt, 20-tick lookahead, and attack-only simulated isDown. A success updates cooldown sampling independently from the Java Random used for Human timing. Settings changes do not retroactively resample nextCooldown. Use settings omit ItemCooldown and MissCooldown.

`Cooldown` receives actual Timer.real_ticks/reset/server_tick_speed/attack delay, with whole-server-tick rounding and unclamped progress. Runtime should reuse the existing `super_knockback_runtime::CombatCooldown` observer, adding a lookahead snapshot method, rather than create another clock or use native attack tick counters. Cooldown enforcement is only the transition to passed, not an every-tick override.

Human uses java.util.Random's 48-bit LCG and cached polar Gaussian, one CPS draw per combo/range, source lognormal mean correction and 10..1000ms clamps. Runtime must supply `Math { log:horizon_core::jmath::log, exp:horizon_core::jmath::exp, strict_log:horizon_core::jmath::fdlibm::log }`; plain defaults use platform math for standalone smoke. JavaRandom's unpredictable default seed uses OS-seeded std RandomState and a unique counter; exact source random-seed identity is not claimed.
