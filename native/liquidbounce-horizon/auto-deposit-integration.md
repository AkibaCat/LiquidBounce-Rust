# AutoDeposit integration

`integrate-auto-deposit.py` validates and installs nine shared sources. `auto-deposit-patch.py` adds three native sources and three actual Game helpers. `scripts/update-auto-deposit-localization.py` updates Simplified and Traditional Chinese catalogs while preserving stable module/config IDs. Pristine upstream and production staging are not written by these owned files.

The complete AutoDeposit tree includes Filter, Items, AutoClose, all InventoryConstraints leaves (including legacy millisecond migration), CheckScreenHandlerType (Types/Filter), CheckScreenTitle (Titles/Custom/Filter, alias CheckTitle), and PunchToDeposit. Its aliases AutoStore and ContainerStorer are registered. The shared screen/item filter implementation is reused from ChestCleaner, with AutoDeposit's own persistent runtime values and translation keys. This retains localized vanilla container-title matching.

PunchToDeposit includes Enabled, Range (3; 1..6), WallRange (0; 0..6, min with Range on change), Delay (5; 1..80 ticks), all four attack SwingModes, PauseOn Combat/UsingItem, ValidStorageBlocks (chest/ender chest), RotateToTarget and the complete noncombat RotationsValueGroup. File and Interop serializers preserve imported finite values rather than treating editor limits as clamps. Unknown item/block IDs retain the source registry fallback semantics. Imported Requires/PauseOn sets mutate in declared order.

Deposit plans submit to the existing shared InventoryManager at normal priority. The source's hotbar-then-main-inventory matching list is captured at the beginning of a plan. Each single QuickMove continuation reads real current menu contents and reevaluates capacity, including effective item components and max-stack-size components. Capacity totals use wrapping i32 arithmetic. The original source only checks whether capacity is positive; this port likewise leaves actual slot acceptance to the real menu predictor/server. It records the captured container's sync ID when perform completes and only closes a container that this module deposited into. Full containers with no available merge/empty capacity receive no repeated clicks. Screen guards and cancellation remain owned by InventoryManager, including its atomic-chain semantics.

Native storage clicking reserves the real prediction sequence and sends ordinary START_DESTROY_BLOCK followed by ABORT_DESTROY_BLOCK with direction DOWN and sequence zero. Silent hotbar selection retains the original ignored-cancellation return and adds no immediate carried packet. The actual held stack's attack-animation component drives local swing; server-visible modes send the normal Punch packet. The wait registers in the common FIFO under AutoDeposit, invalidates stale callbacks on disable, and retries only after its configured tick wait. Pause conditions are checked again before each new action.

Rotation target search uses live outline boxes sorted by vanilla AABB size and nearest shape distance. Target points use a 256-cell projected view-plane grid; an eye inside a box uses the source face-centre grid. Visibility is checked through a raw Outline/None ray, independent of camera-pick modifiers. Visible points use Range, hidden points use WallRange; visible candidates win before hidden candidates, with least angular difference to the block centre. The request runs through the common rotation manager with usage priority 20, considerInventory=true, its own processor range and full smoothing settings. Execution raytraces only the captured target's declared outline with interaction override using the last server rotation, as in the source.

Validation: one concentrated Rust smoke passed (item filter order, empty-stack rejection, localized screen/menu/title acceptance and rejection, punch pause/parent/default boundaries). The nine-source integrator check passed, and the three-source native transformer applied to current staging in read-only memory. The localization updater passed using temporary copies of both catalogs. Subsequent native geometry details received syntax formatting; there was no expanded oracle suite or repeated module smoke. The root task owns the official combined native/engine typecheck and game verification. JOML/Java floating-point differential and real server-specific storage behavior have not been claimed as verified.
