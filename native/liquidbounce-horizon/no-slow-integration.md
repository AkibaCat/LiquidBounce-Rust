# NoSlow integration

The implementation follows the pinned LiquidBounce NoSlow tree: Blocking, Consume, Bow, Bundle, Sneaking, Soulsand, SlimeBlock, HoneyBlock, PowderSnow, Fluid and Slowness. `integrate-no-slow.py` installs the shared engine registration and cumulative native transformer; `scripts/update-no-slow-localization.py` installs Simplified and Traditional Chinese module, setting and choice labels. The game language selects the existing localization catalog.

The behavior model is `native/liquidbounce-behaviors/src/no_slow.rs`. Its runtime service is `engine/src/no_slow_runtime.rs`; its complete configuration codec is `engine/src/config/no_slow.rs`. `no-slow-patch.py` installs the world policy, synchronous local input multipliers, real item-use context, network PRE/POST event, real use/release and attribute helpers. No pristine upstream file is edited.

Blocking includes None, Reuse, Switch, Blink, Interact, Grim-2.3.60, Grim-2.3.64-MC1.8, Grim-2.3.71, InvalidHand and Intave-14.8.4. Consume includes None, both older Grim modes, InvalidHand, Grim-2.3.71, Jump, Intave-14.8.4 and Release. Bow includes None, the three Grim modes and InvalidHand. Bundle retains independent Enabled/Forward/Sideways values. Sneaking includes None, Switch and AAC-5. All independent timing values, NoBlockInteract, OnlySlowOnServerSide, Intave New, block multipliers, Fluid collision and Slowness are serialized through File and Interop formats. Editor ranges are metadata; configuration imports retain finite source values.

Use multipliers replace the original forward and sideways factors independently. Consume running depends on the actual consumable component and active use state; blocking observes the actual server block delay and the interaction tracker. Ordinary predicted uses reserve the real game sequence, while the older Grim untracked sends skip only interaction tracking. Reuse retains the source's additional POST use. Switch retains its source modulo-eight selection arithmetic.

Grim-2.3.71's independent Blocking/Consume/Bow sequences register in the shared coroutine FIFO under `WaitOwner::NoSlow`. They preserve the shared prevent flag and next-tick continuation order. Lifecycle cancellation invalidates stale callbacks. Blink queues ordinary movement packets at priority -500, flushes through the silent sender when blocking ends, and observes real render frames even while the tick timer is frozen. InvalidHand runs at final priority -1000 and sends the actual VarInt hand value -1. Intave's nested replacement uses a thread-local recursion guard. Sneaking modes requiring an old protocol retain the existing missing ViaFabricPlus notification behavior instead of fabricating a modern-protocol sneak packet.

The shared world policy has a thread-local RAII owner scope. By default, and on other threads, world movement properties and flow vectors remain vanilla. Real MotionWorld public movement, block, passenger, jump and fluid entries install ownership only when `client_high_jump_owner && client_side && native_client_queries_allowed()` holds. Server travel/block-damage entries explicitly install false; replay and forecast flags likewise make nested calls false. Nested scopes restore the previous owner on every return. Player fluid queries install their own owner so calls outside the full tick retain correct behavior. Thus LAN guests, server-side body copies, simulated history, other entities and world flow calculations cannot acquire a client policy merely because the module is enabled.

NoSlow wraps `remote_send_state` using its original formatted signature. Step runs last and scans from this wrapper to the unique vanilla yaw anchor, so its packet on-ground replacement lands inside `no_slow_vanilla_send_state`; NoSlow PRE and POST remain outside the complete real movement sender.

Validation performed: the owned integrator checked eight shared files; the native transformer checked fifteen sources in memory against current staging; the one concentrated Rust smoke passed after its fixture supplied a nonzero remaining-use duration for Intave New. The subsequent owner-scope and Step signature corrections received static cumulative-transform validation, with no repeated module smoke. The root task owns the official combined native/engine check and game verification. This handoff does not claim real multiplayer anticheat validation.
