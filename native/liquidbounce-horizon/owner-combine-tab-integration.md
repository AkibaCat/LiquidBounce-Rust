## MobOwners

Projectiles=false. Native event sets a mask: bit0 module running, bit1 projectiles
enabled while running. Actual submitted ownable mobs and projectile render paths
record labels. The native Game renderer draws one NORMAL, shadowed label on
opaque black at half entity height, inclusive 64 blocks, independently of regular
nametags. It does not introduce a see-through label. Owner lookup occurs before
the 64-block cut, as the source does.

`mob-owners-types.rs` is generated by `generate-owner-types.py` from official
26.3 class inheritance. It includes camel_husk, nautilus, zombie_nautilus and Vex;
HappyGhast is not OwnableEntity. Vex uses its actual stored owner reference/counter.
Minecraft client JAR SHA256:
4508d006323f24fa02876310c192d739af56516eb259000ac50f0909a68c9a2d.

Loaded player owners use their live profile name. Other UUIDs use a process cache
with the source Loading/Failed/Canceled strings and formatting. A new UUID starts
an asynchronous, unauthenticated request to the exact pinned Minecraft Services
`minecraft/profile/lookup/{undashed_uuid}` endpoint using Horizon's existing ureq.
Disabling never cancels or clears an in-flight lookup/cache. No engine Cargo
dependency is required. Normal process shutdown ends background threads; there
is no module-disable cancellation transition to invent.

Remote projectile spawn `data` owner IDs are retained separately and cleared on
removal/world reset, because Horizon otherwise discarded the owner of ordinary
remote projectiles. Runtime lookup still requires the actual owner entity to be
loaded. Local projectiles, tridents, rockets, thrown potions and fishing hooks use
their real owner/guest state. The process profile cache is independent of this
per-world remote reference map.

## CombineMobs

CombineArmorStands=false, CombineMinecarts=false. Actual Mob instances always
combine. Key is exact entity type, isBaby (small armor stands included), and full
packed BlockPos. Counters wrap i32 and the first entity consumes its group before
ordinary distance/frustum checks, even when later culled. Player and mannequin
models do not become Mob merely because Horizon stores them in its mob list.

The frame hook clears the render tracker. On module disable invoke
`combine_mobs.disabled()` under the existing module state borrow, or call
`combine_mobs_disabled()` after releasing that borrow. No host effect is needed.
Behavior exposes separate nametag track/count/clear contracts. The event's action
0 tracks rendering, 1 tracks a RenderedEntities/Nametags collection, 2 reads count,
3 clears the nametag tracker. Native ordinary nametags remain ordinary; the source
count text consumer belongs to the not-yet-ported Nametags module. Do not fabricate
an extra count label. Once that real collection is ported, call these contracts at
its source subscription/update boundaries (source clears nametag tracker from
RenderedEntities.onUpdated).

## BetterTab

Complete original settings tree and declaration order: Sorting, Visibility,
ShowGameMode, Limits, Highlight, AccurateLatency, PlayerHider. Original child
toggles/colors/default empty Java regex lists are preserved. Real case-sensitive
FriendBook decides Friends; own profile equality precedes Friends; Others requires
its actual filter match and does not match everyone by default.

Native event serializes actual raw profile/display strings. Engine classifies
hidden/highlight rows using java_regex whole-string matches and produces a scoped
render policy. Hidden players never evaluate Highlight. The actual render policy
performs stable signed-ping/UTF-16 comparators or preserves raw/vanilla order,
filters before limiting, sizes columns with effective height>=1, hides header and
footer, supports NameOnly, adds game-mode suffixes (including source Spectator=S),
numeric 0..9999 colored ping and optional ms, and adds exactly 30 to total width.

Both the display-order cache used by skin residency and layout cache invalidate
on policy change/disable. Latency and display name also join order-cache inputs
while enabled. RAII clears per-frame policy even on early returns.

Malformed imported null regex or negative TabSize remains an explicit error,
not a silently clamped value: engine logs the source failure and renders no rows
for that frame. This contains the Java exception at the native callback boundary;
it cannot unwind a Java exception through Rust FFI. AntiStaff is a separate source
dependency and no fake staff classification is introduced.
